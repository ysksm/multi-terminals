「完了」カテゴリのステータスにしてもローカル状態（環境あり / 完了）は自動では変わりません。Jira タスクと同じく「完了にする」は手動です。

考え方

  1. タスクに「取込元」を持たせる: source = jira | local。一覧・サイドバー・詳細は同じ画面で、取込元バッジ（Jira / 📝 ローカル）で見分ける。環境セットアップ・ワークスペース・作業フォルダの扱いは完全に共通。
  2. 番号は自動採番: 設定の接頭辞 + 連番（既定 T-001…）。Jira 番号と同じ書式なので {KEY} パターン（作業フォルダ・ブランチ名）がそのまま使える。接頭辞は Jira のプロジェクトキーと重ならないよう設定で変更可。
  3. ローカルタスクは編集できる: 概要・説明・優先度・ラベル・リンク・ステータスを詳細画面（と一覧のセレクト）で直接編集し自動保存。Jira タスクの同項目は読み取り専用のまま。
  4. ステータスは自前で持つ: 設定で名前とカテゴリ（未着手 / 進行中 / 完了）を定義。一覧の「ステータス」列は Jira タスクなら Jira の値、ローカルなら自前の値を出す。ローカル状態（未準備 / 環境あり / 作業中 / 完了）とは別物で、従来どおり「完了にする」は手動。
  5. あとから Jira に紐付け: 詳細の「Jira に紐付ける」に番号を入れると Jira から取得して source = jira に切り替える。番号は Jira のものに変わるが、作業フォルダ・ブランチ・ワークスペースはそのまま（ブランチ名は変えない）。逆方向（Jira → ローカル）はしない。
  6. Jira 未設定でも使える: 接続設定が無ければ「＋ タスクを追加」は手動タブだけになり、「Jira を同期」は非表示。タスク管理だけ先に使い始められる。

実装への差分（現状の実装に対して）

Task.Source        … "jira" | "local"（既存データは jira 扱い）
Task.Local         … {Summary, Description, Priority, Labels[], Links[], StatusID}  ※ local のみ
Task.JiraKey       … local では採番した "T-007"（一意性の検査は共通）
Settings.LocalTask … {Prefix "T", Digits 3, NextSeq, Statuses[{ID, Name, Category}]}

API
  POST  /api/tasks            {summary, description, priority, labels, links, statusId, templateId, setup}
  PATCH /api/tasks/{id}       local: summary/description/priority/labels/links/statusId も受け付ける
  POST  /api/tasks/{id}/link-jira {key}   → 取得して source=jira に切替
  GET/PUT /api/task-settings   LocalTask を追加
