導線のまとめ

  1. サイドバーはタブ切替をやめて縦積み: タスク → ワークスペース → アクティブ の順に常時表示。タスクは何十件にもなる前提なので、サイドバーには「作業中 / 環境あり」だけを最大 5 件出し、全件はメインの一覧（フィルタ・並び替え・ページング）に任せる。各セクションは見出しクリックで折りたためて、一覧には高さ上限を付けてワークスペースとアクティブが押し出されないようにする。アクティブ一覧は起動中のペインを全ワークスペース横断で並べ、エージェントの状態（応答待ち / 作業中）を優先して上に出す。タスク一覧がホームになる。
  2. Jira から取り込む: 番号（複数可）→ プレビュー → テンプレート選択 → 「取り込んでセットアップ」で一気通貫。環境は後回しにもできる。
  3. タスク詳細: 左に Jira 情報（読み取り専用 + ローカルメモ）、右に作業環境（フォルダ・ブランチ・リポジトリ・ペイン割当）。ここが環境の編集画面を兼ねる。
  4. 環境セットアップ: ステップ実行ログ。失敗ステップで停止し、再実行 / スキップを選ぶ。バックグラウンド続行可。
  5. ワークスペース: 既存画面の上にタスク帯を出し、タスク詳細 / Jira / ステータス変更へ戻れる。サイドバーのワークスペース名にも Jira 番号が付く。
  6. 設定は右上の ⚙ メニューに集約: 環境テンプレート / ベースクローン / Jira 接続 / リモート設定 / ショートカット一覧。サイドバー下部のボタン群は廃止し、左ペインは一覧専用にする。

内部で持つもの（案）

Task            … jiraKey, summary, status(Jira), fields{assignee,priority,epic,sprint},
                   description, fetchedAt, note(local), localState(none|preparing|ready|working|done),
                   workDir, branch, repos[], workspaceId?
EnvTemplate     … name, workDirPattern, branchPattern, layout, repos[{name, source, setup, panes[]}]
RepoSource      … clone{url} | baseCopy{baseCloneId}
BaseClone       … name, path, defaultBranch, lastFetchedAt, includeNodeModules
SetupRun        … taskId, steps[{kind, cmd, state, startedAt, duration, log}]
  • Task は Workspace とは別集約。Workspace 側は taskId を任意で持つだけにして既存機能を壊さない。
  • ベースクローンの「コピー」は cp -R 前提で描いたが、git worktree add や git clone --reference も候補。node_modules を含めてコピーできるのは cp だけ。
  • セットアップは既存の CloneRepository / git ops の延長で、SetupRun をコマンド + 進捗 push（WebSocket）にする想定。
